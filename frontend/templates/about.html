About GestureConnect

Bilingual Speech and Text to Marathi Sign Language (MSL) Translation System Architecture.

System Architecture & Pipeline Flow

GestureConnect is designed to empower hearing-impaired individuals and assistive communication by bridging English and Marathi text and Marathi speech into Marathi Sign Language (MSL) using a customized 3D humanoid avatar.

END-TO-END TRANSLATION FLOW:
English / Marathi Text OR Marathi Speech
↓ (Speech-to-Text via Google Web Speech / STT API)
Common Text Representation
↓ (Unicode NFC normalization, punctuation & whitespace cleaning)
Text Preprocessing & Tokenization
↓ (English → Marathi controlled lexical mapping if English)
Hierarchical Linguistic Mapping (5 Priorities)
├── Priority 1: Phrase-level matching
├── Priority 2: Exact word-level matching
├── Priority 3: Normalized-form matching
├── Priority 4: Synonym & lexical mapping
└── Priority 5: Out-of-vocabulary character fingerspelling fallback
↓
Canonical Sign Identifiers (e.g. SIGN_HELLO, SIGN_WATER)
↓ (Decoupled Asset Resolution)
Blender-rendered 3D Sign MP4 Clips (/media/animations/)
↓
Sentence-level Sequential 3D Avatar Video Playback
The Canonical Sign Identifier Bridge

A fundamental architectural principle of GestureConnect is the total decoupling between the natural language processing (NLP) layer and the 3D visual animation asset layer. The language layer never directly depends on video file paths. Instead, all text tokens resolve to persistent, standardized Canonical Sign IDs (e.g., SIGN_HELLO, SIGN_WATER).

Out-of-Vocabulary (OOV) Handling

When an input word does not exist as a whole-sign entry in the vocabulary database, it is not dropped or discarded. Instead, it is systematically decomposed into Devanagari or Latin graphemes and mapped to individual fingerspelling sign clips, while simultaneously being logged to the database for administrative review and vocabulary expansion.

Blender 3D Animation Asset Workflow

Blender is used as an offline authoring and rendering tool rather than a heavyweight runtime dependency. The web application plays pre-rendered MP4 video clips sequentially for maximum performance and cross-platform compatibility.

  1. Avatar Modeling: Rig and customize the common humanoid avatar mesh in Blender.
  2. Sign Animation: Animate specific MSL signs using keyframe bones for fingers, wrists, arms, and head posture.
  3. Render & Export: Render the sign clip at 24 FPS with transparent or studio gradient background into H.264 MP4 format.
  4. Asset Placement: Place the MP4 in the designated category directory inside media/animations/<category>/<filename>.mp4.
  5. Database Registration: Register the asset path with its Canonical Sign ID and linguistic metadata via the Django Admin panel or JSON seed file.
  6. Immediate Availability: The translation engine immediately resolves and plays the rendered 3D animation without requiring application restarts.
Technology Stack
  • Backend: Python 3.12, Django 5.1, Django REST Framework
  • Database: SQLite (dev) / MySQL-ready architecture
  • Frontend: HTML5, CSS3, JavaScript, Bootstrap 5
  • Speech Recognition: Web Speech API (mr-IN) + SpeechRecognition API
  • 3D Animation: Blender-authored MP4 clips with humanoid avatar
  • NLP Preprocessing: Unicode NFC normalization, Devanagari tokenizer
Strict Project Scope Boundaries
Per the research specifications, the following are strictly excluded from the current scope:
  • ✕ Sign-to-text / Sign-to-speech recognition
  • ✕ MediaPipe or webcam gesture tracking
  • ✕ CNN / LSTM gesture classifiers
  • ✕ Sensor gloves or external hardware
  • ✕ Generative LLM hallucinations for core translation
