# Multilingual Dictionary & Sign ID Architecture (Stage 4)

This directory contains the central NLP and dictionary linking layer for the **GestureConnect** platform.
It acts as the semantic bridge between input sentences (English/Marathi) and the corresponding sign motion sequences.

## Architecture

1. **Sign IDs (`SIGN_XXXX`)**: Stable, unique identifiers for every unique conceptual sign in the dataset.
2. **Vocabulary**: Contains the complete metadata for every sign, mapping canonical English/Marathi terms to the actual directory paths inside `02_INCLUDE_Dataset_Optimized` and corresponding `03_MediaPipe_Landmarks`.
3. **Language Maps**: Separate mapping indexes to allow Polysemy (one word mapping to multiple possible Sign IDs). 
   - `English` -> `Sign IDs`
   - `Marathi` -> `Sign IDs`
4. **Synonyms**: An extensible list of valid synonyms to increase robustness.
5. **Unknown Words (OOV)**: Keeps track of out-of-vocabulary inputs to trigger fallback strategies later (e.g. spelling out using sign alphabet).

## Directory Layout
- `/English/`: Contains `english_to_sign.json` mapping.
- `/Marathi/`: Contains `marathi_to_sign.json` mapping.
- `/Vocabulary/`: Contains master `sign_vocabulary.json` and `sign_vocabulary.csv`.
- `/Mappings/`: Contains `sign_id_mapping.json` for ensuring IDs stay stable on script reruns.
- `/Synonyms/`: Contains `english_synonyms.json`.
- `/Unknown_Words/`: Contains `oov_words.json`.
- `/Validation/`: Contains `validation_report.json` generated by validation scripts.
- `/Reports/`: Contains `dictionary_report.md` for human-readable stats.
- `/Scripts/`: 
  - `build_dictionary.py`: Parses the dataset and recreates the dictionary (preserves stable IDs).
  - `validate_dictionary.py`: Runs automated integrity checks.
  - `generate_report.py`: Creates summary metrics.

## How to use
To update the dictionary when new dataset folders are added:
1. Run `Scripts/build_dictionary.py`
2. Run `Scripts/validate_dictionary.py`
3. Run `Scripts/generate_report.py`
